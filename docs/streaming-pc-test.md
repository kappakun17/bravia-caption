# PCストリーミング確認（2026-10-11 JST）

初回PCテストと同じCPU・量子化モデル・8.965秒の合成音声を使用。
ローカルHTTPサーバーへWebSocketで16bitモノラルPCMを160msごとに、実時間で送信しました。
モデル読み込みは入力前に完了しています。

- 入力開始から最初の非空字幕イベント受信: 約854ms
- 入力開始から確定字幕受信: 約9.217秒
- 最終結果: 「共和テレビの字幕をテストします。 日本語の音声を文字に変換します。 明日の東京は晴れるでしょう」
- 「今日は」が「共和」に誤認識。オフライン版より精度が落ちました。

854msは入力開始基準で、先頭の無音も含みます。発話開始からの遅延やブラウザー描画時間ではありません。
送信時刻はOSのタイマーに依存します。実音声・地デジ・長時間入力・マイク・TV上での性能は未検証。
字幕画面は作成済みですが、自動確認はページ配信とJS構文まで。ブラウザーのマイク操作はユーザーが開始します。

## 起動

Node.js 22以降を用意し、リポジトリで実行:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-pc.ps1
```

表示された `http://127.0.0.1:8090` をChrome/Edgeで開きます。
WAVを選んで開始すると音声を再生しながら字幕を更新します。
「マイクを開始」ではブラウザーのマイク許可が必要です。
PowerShellでEnterを押すと、このスクリプトが起動した2プロセスだけ終了します。
サーバーは127.0.0.1に限定。外部へ音声を送信しません。

## 再測定

サーバー起動中に別ターミナルで:

```powershell
node .\pc\benchmark.mjs .\samples\japanese-smoke.wav
```

`results/stream-benchmark.json`にイベント時刻と認識結果を保存します（再実行で上書き）。
